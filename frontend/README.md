# Autonomous Research Agent — Frontend

Web UI for the Autonomous Research Agent. It is a **frontend only** project: every
screen reads from and writes to the existing FastAPI backend over its REST API.
No backend code, no mocks, no fake research data lives here.

## Stack

- TanStack Start v1 (React 19 + Vite 8, SSR-capable full-stack React framework)
- TypeScript (strict)
- Tailwind CSS v4 (theme tokens in `src/styles.css`) + shadcn/ui primitives
- TanStack Router (file-based routes) and TanStack Query (client-side fetching + polling)
- Vitest + Testing Library for tests

> **Note on `index.html`:** this stack has no `index.html`, and adding one would
> break the app. The HTML shell lives in `src/routes/__root.tsx` (`RootShell`) and
> is generated by the TanStack Start Vite plugin.

## Requirements

- Node.js 20+ and npm, **or** Bun 1.2+
- The FastAPI backend running and reachable (default `http://127.0.0.1:8000/api/v1`)

## Setup

From this directory (`autonomous-research-agent/frontend/`):

```sh
cp .env.example .env                 # edit if the backend is not on 127.0.0.1:8000
npm ci --legacy-peer-deps            # or: bun install
npm run dev                          # or: bun run dev
```

Open the printed local URL. The app talks to the backend at `VITE_API_BASE_URL`.

### Lockfiles — read this before installing with npm

Two lockfiles ship with this export:

- `bun.lock` — the project's original lockfile. `bun install` works as-is.
- `package-lock.json` — generated for npm. It was resolved with npm's
  `--legacy-peer-deps` mode, so **npm users must keep passing that flag**:
  `npm ci --legacy-peer-deps` or `npm install --legacy-peer-deps`.
  Without the flag, `npm ci` reports the lockfile as out of sync, and a plain
  `npm install` hits an npm resolution bug on this dependency tree
  (`Cannot read properties of null (reading 'edgesOut')`).
  If you would rather not carry the flag, delete `package-lock.json` and run
  `npm install` fresh, or just use Bun.

Verified end to end: `npm ci --legacy-peer-deps`, `npm test` (6 tests passing) and
`npm run build` all succeed from a clean extract of this export.

## Backend contract

All calls go through `src/api/client.ts`, which prefixes `VITE_API_BASE_URL` and
turns failures into readable messages. Endpoints used (`src/api/researchApi.ts`):

| Method + path | Used for |
| --- | --- |
| `POST /research` | Start a job with `{ "topic": "..." }` |
| `GET /research` | List jobs (history) |
| `GET /research/{id}` | Poll a job's status |
| `GET /research/{id}/report` | Fetch the finished report |

Job statuses: `pending`, `running`, `completed`, `failed`.
The UI polls `GET /research/{id}` every 2.5s only while a job is `pending`/`running`,
and refreshes history every 5s only when some job is still active.

## Layout

```text
src/
  api/         client.ts (fetch + error mapping), researchApi.ts (endpoints)
  components/  AppHeader, ResearchInput, ResearchStatus, SourceList, StateViews, ...
  components/ui/  shadcn/ui primitives
  hooks/       useResearch.ts — React Query hooks + polling rules
  lib/         formatting helpers, cn()
  pages/       Dashboard, ResearchProgress, ResearchReport, ResearchHistory
  routes/      file-based routes (thin wrappers that render a page + set <head>)
  types/       research.ts — job/report types
  test/        vitest suites (routing, polling rules)
public/        favicon, robots.txt
```

Routes: `/` (start research), `/research/$id` (live progress), `/report/$id`
(report), `/history` (searchable past jobs).

## Conventions to keep

- `src/routeTree.gen.ts` is auto-generated by the router plugin. Never edit it by hand.
- Route files in `src/routes/` stay thin; page UI belongs in `src/pages/`.
- Fetching is client-side via React Query hooks — do not move it into route loaders,
  since the backend runs on the developer's machine and is not reachable from SSR.
- Never add backend code, mock responses, or placeholder research data to this project.
- `src/lib/lovable-error-reporting.ts`, `error-capture.ts` and `error-page.ts` are
  error-reporting helpers wired into the root error boundary. They are inert outside
  the Lovable editor; delete them and their imports only if you do not want them.
